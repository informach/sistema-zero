# Cancellation and concurrent financial operations

Cancellation now uses the same durable operation ledger as card changes and future explicitly authorized retries. It first persists the cancellation request, retires only unstarted non-cancellation intents, and refuses to race an executing or unknown operation. An existing uncertain debit remains uncertain; this code does not silently declare it failed or retry it. The request stays visible as pending until reconciliation or operational review resolves the blocker.

Every actual execution receives a new UUID fencing token and increments its attempt count. Finishing requires the current token, operation state and execution time. Only CANCEL may be resumed after a bounded reclaim interval; card changes and debits cannot use that path. SQL validates the real subscription/consumer/provider binding and durable cancellation request. A resumed cancellation first GETs the provider and sends no further PUT when the source already reports CANCELED/EXPIRED. The confirmed operation is recorded before local lifecycle persistence, so a later persistence failure remains reconcilable.

The reclaim interval in composition is twice the provider's total retry budget plus thirty seconds, shared with the cancellation scan lease. The same repository instance is injected into both financial services; HTTP test composition also shares it. No raw provider errors or payment tokens enter the operation result or logs. The default service interval remains bounded for isolated tests.

Generated migration 0013 adds executor authority and attempt count. Existing rows with no executor token cannot be finalized using a fabricated authority. Real PostgreSQL tests cover two competing cancellation reclaims, stale executor refusal, durable-request/ownership checks, retirement of an unstarted form, uncertain-debit blocking, and a fresh service instance reconciling a lost cancellation response without another PUT. Focused DB suites initially passed 21 tests / 87 assertions. Payments TypeScript check exits zero with a 1 GiB heap. Final complete regression: 433 tests, no failures/skips, with an additional foreign-consumer assertion checked before commit.

This is not proof of native sandbox cancellation or full recovery activation. Cancellation origin/actor audit, D7 orchestration, operational resolution of uncertain non-cancellation effects, templates, Admin controls and integrated qualification remain outstanding. No real customer subscription was canceled.
