# Hipótese F — entregar o Turtle em um módulo imutável

## Motivo e limite

No perfil D Chrome Pro F1, o worker inicia em aproximadamente 451 ms, enquanto `turtle-protocol.mjs` e as quatro fontes Python começam entre 784 e 785 ms e terminam entre 1290 e 1296 ms. O primeiro desenho aparece em aproximadamente 1495 ms. O experimento E antecipou as cinco requisições, mas piorou as dez amostras editadas; a disputa pela banda agregada explica uma possibilidade, ainda não uma causa fechada. Este lote testa uma variável diferente: reduzir o número de recursos Turtle baixados sem adiantar sua requisição.

## Contrato da mudança

O build gera um único módulo `turtle-protocol.mjs` que contém o protocolo Canvas e as quatro fontes Python **exatamente** como a distribuição as declara. O worker o importa no mesmo ponto temporal de D, converte cada fonte em bytes UTF-8, confere os caminhos fechados e instala os arquivos no mesmo diretório virtual. As quatro fontes individuais continuam na distribuição para exportação, auditoria/licenças e verificação de SHA, mas a execução no navegador não as solicita. Nada no projeto ou numa mensagem escolhe URL, módulo, arquivo, pacote ou versão. A release/distribuição nova terá hashes próprios; a versão da API Turtle e o código Python gerado em Ponte não mudam.

Antes da edição, prova RED no D deve registrar cinco requisições após entrada, inclusive as quatro `/turtle/*.py`. Depois, prova GREEN deve registrar somente o módulo, com `0` requisições das quatro fontes, em Chrome e Edge. O build precisa demonstrar byte a byte a igualdade entre fonte embutida e arquivo individual, inclusive EOL e UTF-8; não basta equivalência semântica. Stop/erro durante import, módulo ausente, fonte manipulada, plain Python e análise continuam fail-closed. Repetir bootstrap e Turtle funcional, fonte autoral que sombreia `turtle.py`, export web e SDK usando a distribuição nova.

Só medir F1 após equivalência funcional e revisão. Usar a mesma máquina, shaping 20 Mbps agregados/80 ms por resposta, três aquecimentos e dez amostras, sem retries/skips, preservando todo erro. Comparar bytes, ordem/tempo das requisições e todas as fases com D, sem trocar metas: frio 12 s, cache 3 s e editado 1,5 s. Reverter F se a prova de bytes, isolamento ou desempenho não sustentar o ganho; D permanece funcional, mas não aprovado. Mesmo se F melhorar, investigar separadamente o timeout de preparação e a falha fria Ponte, antes da matriz de 30 e do computador de 8 GB.

## Estado

Fonte candidata local: `runtimeBundle.ts` empacotou protocolo e quatro textos; `interpreter.ts` importou só o módulo no momento de D, e o builder manteve arquivos individuais com limite de 1 MiB. A prova de compilação com o mesmo `Bun.build` de produção (`loader .py=text`, `minify=true`) confirmou **os quatro arquivos byte a byte**: 1 teste/11 asserções. A primeira tentativa de executar o teste por import direto falhou porque `bun test` interpreta `.py` como caminho sem o loader do builder; a prova corrigida compila antes de importar. Biome passou. A distribuição F `3dc9e5a29be1295b12868ff7c7e9bb3d1f684f4430eebcf6b200a98b5b55da72` compilou; protocolo lógico 165438 B, gzip 37165 B, enquanto D tinha protocolo gzip 1555 B mais quatro fontes de 161714 B. Os arquivos individuais mantiveram SHA idênticos. Bootstrap F **28/28 Chrome/Edge**, inclusive requisição única, módulo ausente, Stop durante import e desenho.

F1 no mesmo perfil 20 Mbps agregados/80 ms, três aquecimentos+dez amostras, sem profiler, sem retries/skips: **13/13 fluxos funcionais**, distribuição F confirmada em todos os 13 attachments. Frio p50 8548 ms (meta 12000), cache p50 1529,3 ms (meta 3000); após edição **8/10 excedem 1500 ms**, mediana 1513,7, mínimo 1497,1, máximo 1597,1. A série D anterior teve 2/10 acima e p50 1480,7. A transferência comprimida menor não melhorou a métrica fim a fim, portanto **F rejeitado**. Não executar SDK/export/matriz30 para o candidato rejeitado. Fonte F revertida. Build posterior com Bun1.3.11 retornou **exatamente D `565bde78c4456704782fd002366b15eeb43c7c599d43e0e37f1927c198126e35`**, e os 39 arquivos físicos comparados por SHA com o rollback D anterior tiveram **zero diferença**. O carregador D restaurado passou seus 7 testes/115 asserções; Biome e `git diff --check` limpos. D continua funcional, porém sem aprovação de desempenho/reliabilidade.
