# Baú Rive Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Animate the unlockable course-trail chest with one Rive state machine while preserving the SVG fallback and server-authoritative reward claim.

**Architecture:** `TrailChest` owns claim state and only starts a visual opening after a successful server response. `ChestRive` is a client-only adapter that loads only when a configured URL exists and reports readiness, load failure, and the terminal `Open` state. `ChestRiveCanvas` is the Rive runtime boundary; it never knows XP, coins, routes, or dialogs.

**Tech Stack:** Next.js 16, React 19, TypeScript, `@rive-app/react-canvas` 4.34, Bun test, Tailwind v4/CSS tokens.

**Spec:** `docs/plans/2026-09-22-bau-rive-design.md`

## Global Constraints

- Keep `POST /api/members/courses/:slug/units/:moduleId/chest/claim` as the only authority for XP and coins.
- Do not mount a Rive canvas during SSR, data saving, reduced motion, or while `NEXT_PUBLIC_KIDS_CHEST_RIVE_URL` is absent.
- Use no duration-based JavaScript completion; Rive terminal-state or CSS animation events finish visual opening.
- Keep the inline SVG as the accessible visual fallback and retain its existing locked/open semantics.
- Rive runtime uses `/rive/rive.wasm`, with the asset CDN disabled.

- [x] **Step 3: Store the confirmed response until a visual completion event finalizes it**

```ts
const reward = pendingClaim.current

if ((reward.xpAwarded ?? 0) > 0 || (reward.coinsAwarded ?? 0) > 0) setReward(...)

```

The CSS fallback receives `onAnimationEnd`; reduced motion calls the same finalizer without starting an animation. The finalizer is idempotent by clearing `pendingClaim` first.
