# BUG-002: Lifecycle confunde classe local com addon Canvas 3D

**Severity:** Medium
**Priority:** P2
**Type:** Functional
**Status:** Fixed

## Environment

- **Build:** 70ca10c6 + worktree atual
- **OS:** Microsoft Windows NT 10.0.26200.0
- **Browser:** não aplicável; reprodução determinística no schema
- **URL:** Studio / validação SZIR / categoria Canvas 3D

## Summary

Uma classe declarada pela criança com nome igual ao de um addon Three.js é classificada como recurso persistente Canvas 3D mesmo quando o projeto não importa Three.js.

## Reproduction

```ts
const result = SZIRSchema.safeParse({
  html: [], css: [], extensions: [],
  js: [
    { type: 'classDecl', name: 'Water', ctorBody: [], methods: [] },
    { type: 'animationLoop', body: [
      { type: 'var', name: 'gota', value: {
        type: 'newExpr', className: 'Water', args: [],
      } },
    ] },
  ],
})
```

Observed before the fix:

- `success: false`.
- Mensagem: `Mova var para fora do laço; este recurso ou configuração deve ser criado uma vez`.

## Expected

`new Water()` deve ser tratado como instância da classe local `Water`. A regra especial de lifecycle só deve valer quando o binding vem comprovadamente de `three` ou `three/addons`.

## Root cause

`isCanvas3DResourceCreatorExpression` decide que todo `newExpr` sem namespace cujo `className` está em `CANVAS3D_ADDON_CLASSES` pertence ao Canvas 3D. A função não recebe a tabela de imports e declarações do escopo.

## Fix

Aplicado em `canvas3dContract.ts`, `programmingReferences.ts` e `schema.ts`. A regra de lifecycle agora recebe o conjunto de classes realmente importadas visível no statement. Um construtor pertence ao Canvas 3D somente com namespace `THREE` ou binding nomeado comprovadamente importado de `three`/`three/addons`; declarações e parâmetros locais fazem shadowing.

## Verification

- PASS — classe local `Water` dentro do loop é aceita.
- PASS — `Water` importado de `three/addons/objects/Water.js` continua rejeitado em `newExpr` e `newInstance` dentro do loop.

## Impact

- **Users Affected:** alunos que criam classes locais com nomes do catálogo de addons
- **Frequency:** sempre para esses nomes dentro de loops
- **Workaround:** não necessário após a correção
