# BUG-001: Atalho invisível em fases sem cano

**Severity:** High
**Priority:** P1
**Type:** Functional
**Status:** Fixed (2026-08-13)

## Environment

- **Build:** worktree local de 2026-08-12
- **OS:** Windows
- **Browser:** reprodução determinística no runtime real
- **URL:** exemplo Reino Zero

## Summary

Fases sem cano ainda recebem um sprite invisível de atalho numa posição padrão. Agachar sobre chão comum nessa posição avança quatro fases.

## Reproduction

Execute o Reino Zero no `examplePlaythroughHarness`, avance até 1-3, ponha o herói em `x=23*16, y=184`, pressione `ArrowDown` e rode um quadro.

Observed before the fix:

- HUD antes: `1-3`.
- HUD depois: `2-3`.
- 18/32 grades não contêm cano, mas mantêm o gatilho.

## Expected

O atalho só deve existir e responder ao comando quando a fase possui um cano de atalho visível.

## Root cause

`levelSpawnPoints` usa coordenadas fallback para `xAtalho/yAtalho` quando `pipeShortcut` retorna `null`, e o laço sempre testa a colisão com `atalho`.

## Fix

O descritor canônico de fase agora carrega `shortcut: null` quando a grade não possui cano. O carregamento deriva `temAtalho` desse descritor e o laço só avalia contato/comando quando a capacidade está ativa; portanto, a hitbox deslocada não é alcançável pela mecânica.

## Verification

- Regressão executada no runtime real para as 32 fases.
- As 18 grades sem cano foram identificadas e o antigo gesto de fallback foi exercitado em cada uma sem alterar o HUD.
- `reinoZeroPlaythrough.test.ts`: 28 pass, 0 fail.

## Impact

- **Users Affected:** todos que jogam as fases listadas
- **Frequency:** sempre, na coordenada do fallback
- **Workaround:** não agachar naquela região invisível
