# BUG-003: Contrato central rejeita `contact` e `inside`

**Severity:** High
**Priority:** P1
**Type:** Functional
**Status:** Fixed (2026-08-13)

## Environment

- **Build:** worktree local de 2026-08-12
- **OS:** Windows
- **Browser:** N/A
- **URL:** build do Studio

## Summary

O schema local da extensão aceita os novos valores de tile de contato, mas a união central `JSStatement` não. O typecheck do Studio falha.

## Reproduction

```bash
cd packages/studio
bun run typecheck
```

Observed before the fix:

- `contact` não é atribuível a `decor | solid | platform`.
- `inside` não é atribuível a `any | head | feet | left | right`.
- Erros aparecem no schema, Reino Zero e testes do runtime.

## Expected

Uma única definição canônica deve tipar os valores aceitos pelo schema, IR, codec, runtime e exemplos.

## Root cause

Os mesmos contratos estão duplicados em `classicIR.ts` e `src/ir/schema.ts`; somente o primeiro foi atualizado.

## Fix

Foi criado `classicContracts.ts` como fonte canônica de papéis, lados e filtros de tile. `classicIR.ts`, `runtimeContract.ts` e `src/ir/schema.ts` agora importam/reexportam o mesmo contrato, sem uniões paralelas para `contact` e `inside`.

## Verification

- `bun run typecheck`: exit 0 em 119,6 s na repetição final.
- O teste semântico isolado de `runtimeContract.ts` resolve e compila o novo módulo canônico.
- `bun test src`: 7.583 pass, 0 fail.
