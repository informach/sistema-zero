# BUG-005: Fonte desconhecida entra na IR tipada do Jogo 2D

**Severity:** Medium
**Priority:** P2
**Type:** Data
**Status:** Fixed (verificado novamente em 2026-08-13)

## Environment

- **Build:** worktree local de 2026-08-12
- **OS:** Windows
- **Browser:** N/A
- **URL:** Ponte código ↔ blocos

## Summary

`SZGame2D.useFont("banana")` é aceito como statement tipado e enviado a um dropdown que só conhece cinco fontes. Isso pode alterar código manual em silêncio no round-trip.

## Reproduction

```bash
bun -e 'import { parseJS } from "./src/parsers/js.ts"; console.log(JSON.stringify(parseJS("SZGame2D.useFont(\"banana\");")))'
```

Observed before the fix:

- Saída: `[{"type":"g2d:useFont","font":"banana"}]`.

## Expected

Id desconhecido deve permanecer como código avançado/raw, como já ocorre no codec equivalente do Jogo 2D Avançado.

## Root cause

O codec básico não compartilha `GAME_UI_FONT_IDS`/`isKnownFont` com o codec avançado e cria IR para qualquer string não vazia.

## Fix

O parser básico passou a validar strings literais contra `GAME_UI_FONT_IDS`; id desconhecido não vira mais `g2d:useFont`.

## Verification

- Antes: parser devolvia `g2d:useFont` para `banana`.
- Depois: parser devolve `memberCall`, preservando o código manual.
- Suíte completa da extensão: 2.603 pass, 0 fail.

## Impact

- **Users Affected:** quem escreve código manual na Ponte
- **Frequency:** sempre com id literal desconhecido
- **Workaround:** usar somente as cinco fontes do dropdown
