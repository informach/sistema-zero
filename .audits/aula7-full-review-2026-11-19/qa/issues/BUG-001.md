# BUG-001: Versão publicada não está nos commits usados pelo deploy

**Severity:** High
**Priority:** P1
**Type:** Data
**Status:** Em correção; fontes versionadas, promoção/publicação pendentes

## Environment

- Revisão de `9614f31afefde0f46078d81f0f5188ba9c7c0d95` mais alterações locais da entrega, em Windows/PowerShell.
- Código publicado conferido por consultas somente leitura ao Railway.
- Data: 2026-11-19T20:44:21.648424+00:00.

## Summary

Os novos componentes, a projeção pública e a migration Auth 0027 existem apenas no trabalho local. HEAD, origin/staging e origin/main não contêm arquivos essenciais, mesmo depois de fetch. Os serviços reais continuam configurados com fontes main/staging, e o workflow de produção faz checkout de main. As versões publicadas pelo CLI não têm commitHash em seus metadados.

## Reproduction

```powershell
git fetch --no-tags origin main staging
git cat-file -e origin/main:packages/member-shell/src/routes/commerce.ts
git cat-file -e origin/staging:packages/auth/src/infrastructure/persistence/drizzle/migrations/0027_profile_public_identity.sql
```

Os dois cat-file retornam 128. O mesmo ocorre para os arquivos novos de contratos e projeção pública. Os 22 serviços estão SUCCESS, mas o código que os compõe não está nas branches versionadas.

## Expected

Todo artefato publicado deve ter seu código e migrations preservados em um SHA revisável e reproduzível nas branches de entrega.

## Root cause

A publicação usou worktrees em detached HEAD com alterações não commitadas. O sucesso do build não incorporou essas alterações ao Git.

## Correção proposta

Versionar somente o escopo desta entrega, preservando Studio/Molda/Pinta em paralelo; integrar nas branches de destino e associar os deploys ao SHA validado. Conferir também a possibilidade de reproduzir e reverter a versão pelo processo normal.

## Verification

Reproduzido nesta rodada; aplicação não alterada durante a revisão. Evidências em `../repros.log` e nos JSON de consultas.

## Impact

Próximo deploy baseado somente no repositório pode remover funções já publicadas ou falhar por incompatibilidade com o conteúdo/migrations. Não houve rollback durante esta revisão.

## Rodada de correção

A entrega e suas migrations foram preservadas nas branches de release; os quatro defeitos funcionais receberam regressões canônicas. PR #275 e branch curada de staging passam pelo CI completo. Recuperação operacional preparada para substituir os 22 uploads por builds de commits explícitos, com plano IaC sem mudanças, triggers nativos desativados, journal da mutação, retirada dos predecessores e prova do SHA em execução. Nenhum metadado foi fabricado e nenhum gate foi desligado. Ver ../correcoes-verificacao.md.
