# BUG-004: Variável genérica perde capacidade 3D

**Severity:** Medium
**Priority:** P2
**Type:** Functional
**Status:** Fixed

## Environment

- **Build:** 70ca10c6 + worktree atual
- **OS:** Windows NT 10.0.26200.0
- **Browser:** N/A
- **URL:** Blockly/SZIR

## Summary

Uma declaração genérica cujo valor é `new THREE.Mesh()` não é reconhecida como objeto 3D pelos pickers nem pelo validador.

## Reproduction

```text
Declare `const cubo = new THREE.Mesh()` com variável genérica + bloco `novo` de Canvas 3D.
Use `cubo` em “liberar objeto 3D”.
```

Observed before the fix:

- `cubo` não aparece no seletor e a SZIR acusa que o recurso não está disponível como objeto 3D.

## Expected

Capacidades devem ser inferidas do valor conectado, independentemente do bloco de declaração usado.

## Root cause

O coletor exclui `newExpr` com namespace e o picker só varre `sz_t3d_new_var`.

## Fix

O coletor registra imports Three/addons e infere capacidades de `newExpr` em declarações genéricas. O picker também inspeciona valores `sz_t3d_new` conectados a `var`/`const` genéricas.

## Verification

- Regressões de símbolos e de `FieldNamePicker` confirmam a capacidade `object3d` sem contaminar classes externas.

## Impact

- **Users Affected:** alunos que combinam Programação e Canvas 3D
- **Frequency:** sempre nessa composição
- **Workaround:** usar “criar nome = novo tipo” de Canvas 3D
