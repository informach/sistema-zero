# BUG-001: `newExpr` contorna o lifecycle de recursos 3D

**Severity:** High
**Priority:** P1
**Type:** Performance
**Status:** Fixed

## Environment

- **Build:** 70ca10c6 + worktree atual
- **OS:** Windows NT 10.0.26200.0
- **Browser:** Chromium via Playwright 1.61.1
- **URL:** Studio / categoria Canvas 3D

## Summary

Um construtor 3D em forma de expressão pode ser encaixado num comando dentro de `A cada quadro`, embora o contrato proíba criar recursos persistentes dentro de loops.

## Reproduction

```text
Monte: A cada quadro → adicionar (novo THREE.Mesh()) em cena.
Converta para SZIR e execute SZIRV2Schema.safeParse(program).
```

Observed before the fix:

- O schema aceita `scene.add(new THREE.Mesh())`; a cena cresce a cada frame.

## Expected

O Studio deve rejeitar criação de recursos persistentes em qualquer profundidade do corpo por quadro.

## Root cause

A validação de lifecycle visita tipos de statement, mas não percorre `newExpr` aninhados nas expressões do statement.

## Fix

O schema agora percorre recursivamente os valores dos statements em loops. O contrato distingue recursos persistentes de valores matemáticos temporários, como `Vector3`.

## Verification

- A regressão rejeita `new THREE.Mesh()` aninhado em loop e aceita `new THREE.Vector3()`.
- `src/three/__tests__/canvas3dSafety.test.ts` passa na suíte focada e na total.

## Impact

- **Users Affected:** crianças que usam construtores técnicos em loops
- **Frequency:** sempre para essa composição
- **Workaround:** declarar o objeto em `Ao iniciar` e apenas atualizá-lo por quadro
