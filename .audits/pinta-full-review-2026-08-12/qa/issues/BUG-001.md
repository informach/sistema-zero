# BUG-001: Backup gerado pode ser irrestaurável

**Severity:** High
**Priority:** P1
**Type:** Data
**Status:** Fixed

## Environment

- **Build:** c9984b60 + working tree de 2026-08-12
- **OS:** Windows
- **Browser:** Independente de browser
- **URL:** Pinta → Galeria → Baixar/Restaurar

## Summary

Um asset aceito pelo modelo pode fazer o Pinta gerar um `.pinta.json` acima de 32 MiB; o fluxo de restore recusa esse mesmo arquivo antes de lê-lo.

## Reproduction

```powershell
@'
const { createVectorBackgroundAsset, sanitizePintaAsset } = await import('./src/core/project.ts')
const { MAX_IMAGE_SRC_CHARS } = await import('./src/vector/model.ts')
const { galleryToPintaJson, MAX_BACKUP_FILE_BYTES } = await import('./src/export/projectJson.ts')
const prefix = 'data:image/png;base64,'
const src = prefix + 'A'.repeat(MAX_IMAGE_SRC_CHARS - prefix.length)
const asset = createVectorBackgroundAsset({ name: 'grande', width: 100, height: 100 })
asset.shapes = Array.from({ length: 112 }, (_, i) => ({ id: `imagem-${i}`, type: 'image', x: 0, y: 0, w: 1, h: 1, src, pixelated: true, fill: 'none', stroke: null, opacity: 1, rotation: 0 }))
const sanitized = sanitizePintaAsset(asset)
const bytes = new TextEncoder().encode(galleryToPintaJson(sanitized ? [sanitized] : [])).byteLength
console.log({ sanitized: sanitized !== null, bytes, restoreLimit: MAX_BACKUP_FILE_BYTES })
'@ | bun -
```

Observed before the fix:

- `sanitized=true`, `bytes=33633813`, `restoreLimit=33554432`.

## Expected

Todo backup que a UI permite gerar deve ser aceito pelo restaurador, ou a operação que ultrapassaria o orçamento deve ser impedida antes de persistir.

## Root cause

O teto de 300.000 caracteres é individual por image shape; não existe orçamento agregado compartilhado com persistência/export/restore.

## Fix

Implementado `galleryBackupByteLength` como medida exata do backup e validação da galeria projetada antes do `setMany`. `PintaStorageBudgetError` leva a causa específica à galeria e ao badge do editor. Estado legado acima do teto continua aceitando mutações que reduzam o tamanho.

## Verification

- `persistence.test.ts` prova a recusa acima de 32 MiB sem gravar e a redução permitida para legado acima do teto.
- Suíte completa e gates finais registrados em `../verification-report.md`.

## Impact

- **Users Affected:** criança com muitos assets/imagens incorporadas.
- **Frequency:** baixa no uso comum, determinística ao atingir o volume.
- **Workaround:** apagar conteúdo até o backup ficar menor; a UI não informa qual conteúdo causa o excesso.
