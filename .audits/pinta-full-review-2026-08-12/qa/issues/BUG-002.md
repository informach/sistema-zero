# BUG-002: Cache de miniatura cruza perfis

**Severity:** Medium
**Priority:** P1
**Type:** Security
**Status:** Fixed

## Environment

- **Build:** c9984b60 + working tree de 2026-08-12
- **OS:** Windows
- **Browser:** Reproduzido com mock funcional de IndexedDB
- **URL:** Studio → Trazer do Pinta

## Summary

Ao trocar o namespace do Pinta, o cache global de miniaturas continua indexado apenas por id/timestamp. Com colisão desses campos, o perfil novo recebe a miniatura do perfil anterior.

## Reproduction

```text
1. No perfil A, persistir vector-background id="mesmo-id", updatedAt=1000, fill vermelho.
2. Chamar listGalleryForStudio().
3. Trocar para perfil B.
4. Persistir o mesmo id/timestamp com fill azul.
5. Chamar listGalleryForStudio().
```

Observed before the fix:

- `firstHasRed=true`, `secondHasBlue=false`, `secondHasRed=true`, `sameThumb=true`.

## Expected

O perfil B nunca deve observar dado derivado do perfil A, mesmo com ids/timestamps iguais.

## Root cause

`thumbCache` usa `asset.id` e `updatedAt`, mas não inclui o namespace e não é limpo por `setPintaStorageNamespace`.

## Fix

O namespace normalizado agora participa da chave do cache junto do id; timestamp e dependência do tileset continuam no stamp de invalidação.

## Verification

- `studioLibrary.test.ts` cobre o mesmo id e `updatedAt` em dois namespaces com fills diferentes.
- Suíte completa e gates finais registrados em `../verification-report.md`.

## Impact

- **Users Affected:** irmãos/perfis no mesmo processo com ids/timestamps colidentes.
- **Frequency:** rara, mas viola uma fronteira explícita de privacidade.
- **Workaround:** recarregar o processo entre trocas de perfil.
