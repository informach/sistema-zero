# BUG-002: Regressão da pesquisa não cobre layout compacto nem confirma autofoco

**Severity:** Low
**Priority:** P2
**Type:** UI
**Status:** Resolved

## Environment

- **Build:** worktree de 2026-08-15
- **OS:** Windows
- **Browser:** Playwright Chromium headless
- **URL:** `packages/studio/e2e/smoke.spec.ts`

## Summary

O teste novo valida a distância somente no viewport desktop padrão. Ele também usa a largura do outline calculada sem antes afirmar que o input está focado; se o autofoco regredir, a área considerada pode diminuir e facilitar um falso positivo.

## Reproduction

```bash
bun run e2e:smoke
```

Observed before the fix:

- o smoke passa 16/16;
- a mesma interação em 375 px falha com gap `-41,2 px`;
- não existe `toBeFocused()` no cenário novo.

## Expected

O E2E da regressão deve provar o comportamento no layout vertical e no horizontal e confirmar que o estado visual medido inclui o autofoco real.

## Root cause

O cenário herdou o viewport desktop do projeto Playwright e não parametrizou o breakpoint de 440 px. A medição consulta estilos de foco, mas não trava a precondição de foco.

## Fix

Resolvido em 2026-08-15. `smoke.spec.ts` agora reutiliza o mesmo contrato geométrico no desktop e em 375×812, afirma `toBeFocused()` antes de medir o halo e valida tanto a instrução quanto o primeiro bloco encontrado.

## Verification

- smoke atual: 16/16 PASS;
- matriz externa 1280/768/375: o caso de 375 revela a falha que o smoke não detecta.

After the fix:

- cenário focado da pesquisa: 2/2 PASS;
- smoke completo: 17/17 PASS;
- o cenário compacto falhou antes da correção de BUG-001 e passou depois.

## Impact

- **Users Affected:** manutenção e futuras regressões; indiretamente, usuários compactos
- **Frequency:** sempre que o smoke é executado sem matriz responsiva
- **Workaround:** executar uma matriz Playwright adicional
