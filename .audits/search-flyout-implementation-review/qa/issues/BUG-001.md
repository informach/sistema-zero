# BUG-001: Busca continua sobrepondo conteúdo no layout compacto

**Severity:** High
**Priority:** P1
**Type:** UI
**Status:** Resolved

## Environment

- **Build:** worktree de 2026-08-15
- **OS:** Windows
- **Browser:** Playwright Chromium headless
- **URL:** playground do `@sistemazero/studio`

## Summary

Em contêineres menores que 440 px, abrir “Pesquisar” deixa a instrução e o topo dos resultados atrás do input. O defeito é determinístico em todo o layout horizontal.

## Reproduction

1. Abra o Studio com largura de 375 px.
2. Crie um projeto básico.
3. Abra “Pesquisar”.
4. Observe “Escreva para achar”.
5. Digite `criar` e observe o primeiro grupo e os blocos.

Observed before the fix:

- gap pintado em 375 e 439 px: `-41,2 px`;
- instrução/rótulo inicia em `y=168,3`, dentro do input pintado até `y=209,5`;
- o primeiro bloco inicia em `y=166,4`, também atrás do input;
- em 440 e 441 px, já no layout vertical, o gap é `10,1 px`.

## Expected

Input, halo de foco, instruções, cabeçalhos e blocos devem ter pelo menos 8 px de separação visível em layouts vertical e horizontal.

## Root cause

O espaço é criado por `{ kind: 'sep', gap: ... }`. No `VerticalFlyout`, o separador reserva altura e a correção funciona. Abaixo de 440 px, `BlocklyPanel` ativa `horizontalLayout`; o `FlyoutSeparator` então ocupa o eixo X, não o Y. O input permanece absoluto sobre uma faixa vertical, portanto aumentar o `gap` apenas desloca os resultados para a direita e não cria espaço abaixo dele.

## Fix

Resolvido em 2026-08-15. O Studio agora configura `SearchAwareHorizontalFlyout`, uma extensão oficial do `HorizontalFlyout` que reconhece um marcador sem DOM e soma a faixa do campo no eixo Y e na altura do painel. O layout vertical continua usando `sep`. A reserva inclui input, inset, halo de foco e 8 px de respiro.

## Verification

- desktop 1280×720: PASS, gap `10,1 px`, último bloco alcançável;
- tablet 768×1024: PASS, gap `10,1 px`, último bloco alcançável;
- mobile 375×812: FAIL, gap `-41,2 px` nos três estados;
- sondagem do breakpoint: 439 FAIL; 440 PASS.

After the fix:

- E2E 375×812: PASS para instrução e primeiro resultado, com gap pintado mínimo de 8 px;
- desktop: PASS para instrução com o mesmo contrato;
- smoke completo: 17/17 PASS;
- programação/acessibilidade: 5/5 PASS.

## Impact

- **Users Affected:** todos os usuários em contêineres compactos abaixo de 440 px
- **Frequency:** sempre
- **Workaround:** usar largura de pelo menos 440 px
