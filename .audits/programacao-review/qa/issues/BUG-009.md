# BUG-009: Consumidores aceitam nomes livres

**Severity:** Medium  
**Priority:** P2  
**Type:** UI  
**Status:** Open

## Environment

- **Build:** `9c5bb92c`
- **OS:** Windows
- **Browser:** N/A
- **URL:** múltiplos blocos Programação

## Summary

Campos que referenciam funções, variáveis, elementos e contextos existentes ainda usam texto livre em vez de picker contextual.

## Reproduction

```text
Abrir os campos HANDLER de evento nomeado, FN de timeout e SOURCE/TARGET de object assign.
```

Observed before the fix:

- Os campos permitem qualquer nome e não oferecem símbolos disponíveis.

## Expected

Consumidores devem selecionar nomes válidos; declarações continuam editáveis.

## Root cause

Migração parcial para `FieldNamePicker` e ausência de alguns tipos contextuais, como ID HTML cru.

## Fix

Pendente: inventário e migração dos consumidores, com novos tipos de picker quando necessário.

## Verification

- Teste gerado que distingue campos declaradores e consumidores.

## Impact

- **Users Affected:** todos, especialmente iniciantes
- **Frequency:** ao usar os blocos afetados
- **Workaround:** digitar exatamente o identificador

## Automation Follow-up

- **Required:** Yes
- **Status:** Pending
- **Spec / Command:** testes de definições e FieldNamePicker
- **Notes:** Não transformar campos declaradores em seletores.
