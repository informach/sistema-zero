# BUG-004: colisão máxima de tilemap custa cerca de 100 ms

**Severity:** Medium
**Priority:** P2
**Type:** Performance
**Status:** Open

## Environment

- **Build:** game-2d 0.57.0, worktree corrente sobre `8c97ae05`
- **OS:** Windows NT 10.0.26200.0
- **Browser:** benchmark headless com Bun 1.3.11
- **URL:** runtime `SZGame2D.collideTileMap`

## Summary

Uma única colisão permitida pelo próprio orçamento do runtime pode visitar
262.144 células e executar busca linear em uma lista de 512 sólidos para cada
célula, consumindo aproximadamente 100 ms.

## Reproduction

```bash
# Montar map 512x512, solid=[0..511], todas as células 511;
# colidir um sprite 512x512 que cobre o mapa e medir performance.now().
```

Observed before the fix:

- 128x128: 11,35 ms
- 256x256: 28,62 ms
- 512x512: 100,63 ms

## Expected

Uma chamada no limite documentado deve permanecer dentro de um orçamento de
quadro razoável ou ser recusada/fatiada com feedback didático.

## Root cause

`isSolidCell`/`isPlatformCell` usam `Array.indexOf` dentro de dois loops cujo
limite combinado chega a 512x512.

## Fix

Não aplicado. Cachear membership em `Set`, limitar células por chamada e criar
benchmark de regressão.

## Verification

- Benchmark repetível no runtime real.
- Testes atuais validam terminação, mas não o orçamento temporal.

## Impact

- **Users Affected:** projetos com mapas/sprites/colisores muito grandes
- **Frequency:** por quadro enquanto a colisão máxima estiver ativa
- **Workaround:** reduzir mapa, sprite ou área de colisão visitada
