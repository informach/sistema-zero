# L2 — instalação dos clientes e atualização do desktop

## Entrega e revisão

- A lacuna de preparação por terminal foi fechada para Windows x64. A interface instala Codex 0.162.1 e Claude Code 2.1.299, versões usadas nos adaptadores validados. Os downloads vêm diretamente das distribuições oficiais; tamanho e SHA-256 estão fixados no catálogo versionado do app. O Codex inclui o pacote completo, com Code Mode e recursos auxiliares. Não executa scripts remotos, não depende de npm/Node global e não altera as instalações externas ou credenciais.
- Instalação usa staging próprio, valida arquivos/versão e troca a seleção atomicamente. Cancelamento/falha preserva a seleção anterior; nova tentativa limpa somente staging e versões não selecionadas do instalador. Reabertura confere os hashes de todos os arquivos, recusa vínculos/arquivos adicionais e oferece reparo. Arquivos e caminhos de pacote não são fornecidos pelo renderer.
- A prova identificou que `claude auth status --json` retorna código 1 em logout normal. O adapter agora interpreta esse resultado estruturado e apresenta Conectar, em vez de uma falha genérica de execução. Codex ainda reconheceu a conta existente do Windows no perfil isolado; não declarar primeiro login como comprovado.
- Atualização integrada com electron-updater **6.8.9**, compatível com electron-builder **26.15.3**, sem adotar APIs da documentação v27. Verificação na abertura e a cada seis horas; download e reinício explícitos, cancelamento e estados visíveis. Não instala automaticamente ao sair. Antes do reinício, recusa produção em andamento; encerra IPC/sincronização e fecha os bancos antes de iniciar o instalador.
- Manifesto só aceita versão estável, um NSIS com SHA-512/tamanho e arquivo dentro da pasta HTTPS configurada. Downgrade e prerelease desabilitados. Publicadores completos e URL pública são incorporados ao ASAR; não existem segredos ou feed fictício no pacote.
- A inspeção de `electron-updater/out/windowsExecutableCodeSignatureVerifier.js` mostrou que o verificador padrão pode aceitar a atualização quando PowerShell/ConvertTo-Json está indisponível. Foi usado o **hook público de verificação**, com processo PowerShell absoluto, sem shell, `LiteralPath`, limite de tempo, saída validada, status Valid e Subject completo exato. A mesma verificação obrigatória ocorre depois do download e antes do reinício, inclusive se o YAML externo omitir publisherName. Falha do verificador recusa a operação.
- `bun run package` exige feed/publicadores e certificado real, mantém forceCodeSigning e `--publish never`. Sem configuração, recusa antes de produzir artefato. Nenhum certificado foi comprado, nenhum feed foi criado/publicado, nenhum instalador do Sistema Zero foi declarado assinado.

## Evidências

- Desktop: **85 testes, 1.871 asserções**, zero falhas; SQLite/Node: **19 testes**, zero falhas. Novos testes conferem corrupção/truncamento/tamanho, redirecionamento não autorizado, cancelamento, alteração/ausência/adição de arquivos, preservação durante limpeza, traversal/symlink no tar, limites do manifesto e configuração obrigatória. Logs `.cache/tests-desktop-updates.log` e `.cache/tests-client-install-local.log`.
- Typecheck zero erros: `.cache/types-desktop-updates-final.exit=0`. Biome: **183 arquivos**, sem alterações, `.cache/check-desktop-updates.exit=0`. Build completo Electron/renderer/captura/Remotion: `.cache/build-desktop-updates.exit=0`; aviso existente de chunks grandes do Studio continua registrado.
- Electron real: perfil `packages/marketing-desktop/.cache/client-install-proof/38f0c41b-2f6d-4be3-bce5-aa80c6a14397`. Os dois botões baixaram os clientes oficiais, executaram a validação de versão e gravaram seleção/recibo. Um segundo processo reabriu, conferiu todos os hashes e reconheceu ambos. Logs `proof-client-install-v2` e `proof-client-install-reopen-final`, código 0. Capturas `before.png`, `installed.png`, `reopen.png`; a última foi inspecionada após a interface de atualização e a mensagem de logout do Claude serem incorporadas.
- A primeira prova de perfil isolado encontrou PATH com chaves de capitalização diferentes no Windows; o lançador de prova agora remove as variantes antes de definir o PATH isolado. A segunda demonstrou instalação, mas a asserção de ausência de conta era incorreta por credencial já existente no Windows. Nenhuma conta foi encerrada. A prova final usa critério de instalação/reabertura, sem inventar prova de primeiro login. Logs anteriores conservados.
- Authenticode real: `.cache/proof-update-signatures.exit=0`. Cliente oficial Claude assinado pela Anthropic aceito; outro publicador, arquivo sem assinatura, binário alterado e verificador inexistente recusados. Caminho contendo aspas foi processado sem execução de comando adicional. Evidência em `packages/marketing-desktop/.cache/update-signature-proof/evidence.json`. Não houve execução dos binários adulterados nem do instalador de revisão.
- `bun run scripts/package-release.ts` sem configuração falhou conforme esperado, antes de build/publicação. É uma prova negativa, não um pacote final.

## Critérios ainda externos

L2 continua aberto para primeiro login assistido em instalação sem credenciais, certificado/feed de distribuição e atualização entre duas versões assinadas, além do piloto físico de duas máquinas. A implementação de instalação/atualização está presente; as provas acima não substituem esses critérios. Não houve Docker, deploy ou push nesta entrega.
